## 尖刺死亡判定修复：判定区跟随用户画的碰撞体积

### bug 根因
刺同时有"实心碰撞体"（StaticBody2D，layer=1 挡人）和"死亡判定区"（HazardArea，同形状多边形）。鸡被实心刺挡住后**进不了判定区内部**（Godot shape overlap 需要严格内部相交，鸡被 safe margin 挡在表面外）→ 碰刺不死/判定区域不准。
另外 HazardArea 的多边形是手工复制的一份，用户改刺碰撞体后不会自动跟随。

### 修复（2 处小改）
1. **spark.tscn**：`StaticBody2D.collision_layer = 0`——刺不再推挤/挡住玩家，鸡能进入刺区域触发判定（进入即死，死亡立即传送，视觉无穿帮感）。
2. **spark.gd**：新增 `_sync_hazard_shape()`（_ready 调用）——运行时把 `StaticBody2D/CollisionPolygon2D.polygon`（用户画的刺碰撞体积）**动态复制**给 `HazardArea/CollisionPolygon2D.polygon`。用户以后在编辑器里改刺碰撞体，死亡判定自动跟随，无需改 HazardArea。

### 验证
- 临时脚本：`hazard_polygon_matches_src=true`（判定多边形=用户画的体积，8 顶点）；`src_layer=0` ✓
- 完整运行关卡 150 帧无错误 ✓

### 备注
- 用户把 spark.gd 默认参数改成了 retract_distance=50、move_speed=80（原 18/40）——实例未覆盖时用新默认值。
- 若未来需要刺"实心挡人"（视觉不穿帮），需把判定区做成略大于实心体（hazard_scale>1），但那样判定区就不是精确的用户画的体积了；当前按用户要求：精确体积 + 不挡人。

## 修复：trigger 按钮运行时变小（脚本覆盖用户调好的尺寸）

### bug 根因
trigger.gd `_ready` 里 `_sprite.scale = Vector2(sprite_scale=0.15)` 强制覆盖 Sprite2D 缩放，再叠加上关卡实例 scale(0.2) → 运行时视觉 = 640×0.15×0.2 = 19.2px；而编辑器里（_ready 不跑）显示 640×0.2 = 128px。**编辑器所见 ≠ 运行时所得**。另外 `_setup_collision_shape()` 运行时按贴图尺寸重算碰撞体 size/position，覆盖用户手动调的碰撞（用户后来把碰撞体调成 (320,122)/(0,29) 也被覆盖）。

### 修复原则（重要约定）
**脚本不覆盖用户在编辑器里调好的任何视觉/碰撞尺寸**——"编辑器所见即运行时所得"。删掉：
- `@export sprite_scale` + `_ready` 里的 `_sprite.scale = ...`
- `_setup_collision_shape()` 自动适配（连同 tscn 里的 `sprite_scale=0.15`、`_collision` onready 引用）
用户后续在 tscn/编辑器里直接调 Sprite2D scale 或 CollisionShape2D 即可，脚本只做逻辑（贴图切换/计数/联动）。

### 验证
- 临时脚本：sprite_scale=(1,1) 不被覆盖；visual_world_width=128（=640×实例0.2，编辑器所见一致）；collision_size=(320,122) position=(0,29) 保持用户设定 ✓
- import + 关卡 200 帧无错误 ✓

### 教训
做"自动适配/封装"功能时容易破坏用户手动配置——**凡用户可能在编辑器里手调的值（scale、碰撞体），脚本一律只读不写**；自动适配只适合"无手调默认值"场景（如 spark 的 shader 裁剪线由 @export 显式给）。

## 修复：鸡站在蛋上下蛋 → 新蛋永久穿模

### bug 根因
"下蛋瞬移免碰撞"原实现：**鸡与蛋连续分离 ignore_restore_delay(0.3s) 才恢复 Player 碰撞**，用 `_overlaps_chicken` 数学判定重叠，重叠就重置分离计时。
鸡站在蛋上（垫脚）下蛋时：新蛋生成在鸡脚下方（鸡中心 +16px），**蛋中心落在鸡碰撞体（半高18）内** → 鸡踩在新蛋上时几何恒"重叠" → 分离计时永被重置 → 免碰撞永续 → 永久穿模。

### 修复（EggBase.gd）
改为**固定时长免碰撞窗口**：`_ignored_chicken` 存在时 `_separated_time += delta`，到 ignore_restore_delay 无条件 `_ignored_chicken = null` + 恢复 Player 碰撞。删除 `_overlaps_chicken()`（不再使用）。
为什么安全：下蛋必反冲跳起（-320），0.3s 内位移 -52px 必已分离，恢复时鸡在空中不会挤开蛋；鸡落回新蛋上时碰撞已恢复 → 正常站蛋。

### 验证
- 临时脚本（鸡与蛋刻意重叠）：`mask_during=5`（World|Egg 免Player）→ 0.5s 后 `mask_after=7`（World|Player|Egg 恢复）+ `ignored_chicken_cleared=true` ✓
- import + 关卡 200 帧无错误 ✓

### 教训
"分离才恢复"类免碰撞逻辑在"物体持续接触（站上去）"场景会死锁；**短暂窗口（定时器无条件恢复）比条件恢复更稳**。

## 修复：新蛋落在旧蛋上不激活碰撞（"被移动过才有碰撞体积"）

### bug 根因（第二层：落地激活判定）
蛋初始 `collision_layer=0`（空中无碰撞，设计如此），靠"落地检测"`_check_on_ground()` 激活完整碰撞（layer=4）。
但落地检测**只认 World 层**：射线 `q.collision_mask = LAYER_WORLD`、body_entered 只认 StaticBody2D/TileMap。新蛋落在**另一个蛋**（Egg 层 layer=4）上时（蛋梯/垫脚场景），射线查不到支撑 → 永不激活 → 保持 layer=0 → 鸡对它永久无碰撞（穿模）。蛋一旦被踢动滚到地面上（World）才激活 → 正是"被移动过才有碰撞体积"的现象。
另外原距离判定 `<12.0` 也偏严（蛋半径 14，中心距支撑面约 14px，永远 false，兜底射线实际失效，只靠 body_entered）。

### 修复（EggBase.gd 两处）
1. `_check_on_ground()`：射线 mask 改为 `LAYER_WORLD | LAYER_EGG`（蛋可垫在蛋上）；距离判定放宽 `< 20.0`（半径 14 + 接触间隙）。
2. `_on_body_entered()`：支撑判定加 `body is EggBase`（蛋与蛋互垫）。

### 验证
- 临时场景：蛋 A 落地激活（layer=4），蛋 B（初始 layer=0）落在 A 上 → 2s 后 `egg_b landed=true layer=4`（修复前保持 layer=0）✓
- import + 关卡 200 帧无错误 ✓

### 关联记忆
- 蛋"空中无碰撞"设计：collision_layer=0 + mask=World（只落地面停下）；激活后 layer=4（Egg）+ mask=World|Player|Egg。
- 项目层数值：World=1, Player=2, Egg=4（layer_3），Mechanism=8（layer_4），Collectible=16，OneWay=32。
