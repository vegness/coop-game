# 2026-08-14 工作日志

## 门压鸡修复加固 + 复活闪烁

### 排查：门压鸡"没有修好"
用真实 level_01.tscn 实例化 + 模拟"开门→鸡站门下→关门"完整链路 headless 复现，结果：**revive 实际是生效的**（鸡从 (2980,632) 被传送到 (3034,632)）。但捕获到一个真实报错：

```
ERROR: Can't change this state while flushing queries. Use call_deferred() or set_deferred()...
   at: body_set_shape_disabled
   [0] revive (ChickenBase.gd:672)  ← collision_shape.disabled = false
   [1] _on_crush_body_entered (door.gd:100)
```

根因：`revive()` 在 Area2D 的 `body_entered` 回调（物理查询 flush 期间）里直接 `collision_shape.disabled = false`，Godot 4.6 的 CollisionShape2D setter 不早退（即使值相同也触发 `body_set_shape_disabled`）→ 报错。当前流程里 `die()` 从不被调用（只有 `revive()` 直接调用），所以 `disabled` 恒 false，报错是"无害噪声"；但若未来接 `die()`，flush 期间改状态会**被丢弃**导致碰撞恢复失败。

### 修复（ChickenBase.gd）
1. `revive()`：改成 `if collision_shape.disabled: collision_shape.set_deferred("disabled", false)` —— 只在确实禁用时、用 set_deferred 延迟到安全时机恢复，消除 flush 报错。
2. **复活闪烁（新需求）**：`revive()` 末尾调 `_start_respawn_blink()`；`die()` 加 `_kill_blink()`。实现：
   - const：`RESPAWN_BLINK_DURATION=3.0`、`RESPAWN_BLINK_MIN_ALPHA=0.4`、`RESPAWN_BLINK_PERIOD=0.2`
   - `_start_respawn_blink()`：用 create_tween 链 15 组（0.1s→0.4、0.1s→1.0）共 3s，`tween_callback(_on_blink_finished)` 收尾复位 1.0
   - `_on_blink_finished()` / `_kill_blink()`：杀旧 tween + `sprite.modulate.a = 1.0`
   - 统一走 `revive()` → 掉坑/尖刺/门压所有复活都闪烁

### 修复（door.gd 加固）
- 新增 `_crush_area` 引用 + `_physics_process` 每帧 `get_overlapping_bodies()` 兜底轮询（`body_entered` 可能因门体实心挤压时序漏判/迟到）
- 把压击逻辑抽成 `_try_crush(chicken)`，`body_entered` 和轮询都走它；免疫表（0.8s）+ 复活点偏移防死循环不变

### 验证
- 真实关卡复现：`revived=true final_pos=(3034.0,632.0)`（无 flush 报错）
- 闪烁采样：`blink min_a=0.41 max_a=1.00`、`blink_final_a=1.00`
- import + 完整关卡 200 帧无错误

### 教训（长期）
- **Area2D `body_entered`/`body_exited` 回调期间改碰撞形状状态（`disabled`/`collision_layer`/`collision_mask`/`monitoring`）会报 "flushing queries" 错误且状态变更被丢弃**。改碰撞状态必须用 `set_deferred` 或 `call_deferred`。
- `sprite.modulate.a` 已被 GhostEgg（子类）占用（0.5/1.0），闪烁用 0.4/1.0 且结束后复位 1.0，与幽灵机制暂不冲突（幽灵未在 level1 用）。

## 修复：门抬起时小鸡跳跃被误判死亡

### bug
门压鸡用了"CrushArea 检测重叠即判死"（body_entered + 每帧轮询），但没判断门当前是否在"关闭/落下"状态。门抬起（activate，门下空间可通行）时，小鸡在门下**二段跳**（碰撞体 top 可到 488，CrushArea 打开时 bottom 530）会进入 CrushArea → 被误判死亡。

### 修复（door.gd）
加状态标记 `_can_crush`：
- `_ready`：`_can_crush = not start_open`（初始关闭才可压）
- `_on_activate()`（门抬起）：`_can_crush = false` → 门下空间可通行，不判压击
- `_on_deactivate()`（门落下）：`_can_crush = true` → 门下小鸡会被压死
- `_try_crush()` 开头加 `if not _can_crush: return`

### 验证（headless 真实关卡）
- 门打开时小鸡固定门下（深入 CrushArea 15 帧）：`immunity_during_open={}` 空 + `fell_off_during_open=0` → 不误判 ✓
- 门落下：`immunity={Chick_1}` + `fell=1` + revive 到 (3034,632) → 正常判死复活 ✓
- import + 完整关卡 200 帧无错误 ✓

### 教训
"区域检测判死"类机关（门压/尖刺）要区分**机关状态**：只在机关"正在造成危险"时才判死，机关"处于安全态/让路态"时即使检测区重叠也不判死（否则玩家在让路态的正常移动/跳跃会被误伤）。

## 修复：跳跃/下蛋组合逻辑（一次腾空 2 跳 + 1 蛋）

### bug（2 个）
1. **跳 1 → 下蛋 → 二段跳 失效**：`_handle_jump_input` 的二段跳分支只认 `JUMPING/FALLING` 状态，下蛋后是 `EGG_LAID`，不满足 → 空中按跳无效。
2. **地面直接下蛋 → 一次跳都放不出**：同样因为 EGG_LAID 不在可跳状态。

### 设计（用户要求：一次腾空总共 2 次跳跃 + 1 次下蛋，顺序任意）
- 用 `jump_count_used: int` 替代 `has_used_air_jump: bool`，一次腾空跳跃预算 `MAX_AIR_JUMPS = 2`（地面起跳 =1，空中跳 +=1，上限 2）
- `_handle_jump_input` 空中可跳状态加入 `EGG_LAID`：`jump_count_used < MAX_AIR_JUMPS or can_air_jump_after_stomp`
- `_handle_egg_lay_input` 加 `if has_laid_egg_this_cycle: return`——`has_laid_egg_this_cycle` 从"只写不读的死标记"变成真正的一次腾空 1 蛋限制（落地/起跳重置）
- 滑翔条件改 `jump_count_used >= MAX_AIR_JUMPS`（跳跃预算用尽才可滑翔）
- 重置点：`_perform_jump`（=1）、`_on_landed`（=0）、`revive`（=0）

### 兼容性
- `InfiniteChicken`（无限鸡）覆盖 `_perform_egg_lay` **不设** `has_laid_egg_this_cycle = true` → 绕过 1 蛋限制，可无限下蛋（其注释本来就写了这个设计意图）✓

### 验证（headless 输入模拟，已删临时脚本）
- 场景 A：跳1(jump_used=1) → 下蛋(EGG_LAID) → 二段跳(jump_used=2) ✓
- 场景 B：地面下蛋(EGG_LAID, jump_used=0) → 跳1(1) → 跳2(2) ✓
- 场景 C：跳 → 下蛋 → 再下蛋，`eggs_gained=1`（第二次被拦截）✓
- import + 完整关卡 200 帧无错误 ✓

### 测试技巧
- headless 模拟输入：`Input.action_press(action)` → `await physics_frame` → `Input.action_release(action)` → `await physics_frame`（`is_action_just_pressed` 只在按下一帧 true）
- 下蛋有 3s 冷却（egg_lay_cooldown_timer），连测多个下蛋场景要先清零。
