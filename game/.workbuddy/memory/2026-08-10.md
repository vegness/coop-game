## 下蛋瞬移免碰撞：鸡与蛋互不挤开（分离后恢复）
用户反馈：地面下蛋瞬间蛋的碰撞体积会把鸡向左右挤开。要求：下蛋瞬间鸡↔蛋不算碰撞，蛋蛋/蛋世界碰撞全保留，鸡蛋分离后恢复。

### 根因（重要）
**Godot 碰撞规则：CharacterBody2D.move_and_slide() 只检查"自己的 mask & 目标 layer"，不检查目标 body 的 mask！** 只改蛋端 mask 排除 Player 层没用——鸡 mask=21（含 Egg=4）照样撞蛋被推。**必须改鸡端 mask**。

### 修改
- **ChickenBase**：`_perform_egg_lay` 时 `collision_mask = _base_collision_mask & ~4`（排除 Egg 层）+ `_egg_ignore_timer = egg_ignore_duration(0.3s)`；`_physics_process` 递减计时、到期恢复 `_base_collision_mask`（`_ready` 记录初始值）
- **EggBase**：`set_ignore_player(chicken)`（下蛋鸡引用）→ `_update_collision_mask()` 排除 Player 层（保留 World|Egg）；**分离恢复需连续分离 `ignore_restore_delay=0.3s`**（蛋端 `_separated_time` 累加）——反冲跳起的短暂分离不算，否则鸡落回蛋边又被挤开；几何重叠检测 `_overlaps_chicken`（矩形-圆最近点 < 半径，站蛋上=相切不算重叠→恢复）
- ChickenBase._spawn_egg 在 spawner.spawn() 返回后对 spawned 调 set_ignore_player（spawn_function 创建的实例才是实际蛋，_create_egg 的临时 egg 会被丢弃）
- ⚠️ 用户调整：免碰撞时长 0.8s → **0.3s**（鸡端 egg_ignore_duration 与蛋端 ignore_restore_delay 同步改）

### 验证（4 项 PASS）
下蛋瞬间 dx=0.0（鸡纹丝不动）/ 分离 0.8s 后蛋 mask 恢复含 Player / 恢复后鸡可站蛋上 / 蛋蛋互斥保留（gap=133）
- **坑**：仅改蛋 mask 无效（move_and_slide 只看自己 mask）；分离检测必须加时间阈值（0.8s），瞬时分离（反冲跳起）会误恢复
- 回归 MainMenu / CharacterSelect / Level01 零错误

## 修复联机 bug：看不到朋友的小鸡（蛋能正常出现）
用户反馈：联机时只有自己的小鸡，朋友的小鸡不出现；但下的蛋能正常出现。

### 根因
`LevelBase._spawn_players` 多人模式 `count = 1`——每端只生成自己的 1 只鸡。注释假设"其他端通过 MultiplayerSynchronizer 看到"，但 **MultiplayerSynchronizer 只能同步已存在的节点**（NetSync 配置 spawn=false 只同步 position/rotation），其他端根本没有朋友的鸡节点 → 看不到。蛋能出现是因为走 MultiplayerSpawner（spawn 广播 + 各端自动生成）。

### 修改
- **LevelBase._spawn_players**：多人模式 `player_ids = [my_peer_id] + multiplayer.get_peers()`（**排序**保证各端节点路径一致）→ 每端生成所有玩家的鸡，每只 `set_multiplayer_authority(pid)` + 按 `player_colors.get(pid)` 上色
- **Level_01**：`_make_spawn_marker` → `_make_spawn_markers()` 生成 4 个水平出生点（spawn_position + x*60）
- **ChickenBase._is_network_client 加固**：peer 断开时报 "multiplayer instance isn't currently active"——用 `multiplayer_peer.get_connection_status() != CONNECTION_CONNECTED` 提前 return（⚠️ ENetMultiplayerPeer 没有 is_server()，Godot 4.6 用 get_connection_status）

### 验证（双实例 ENet，两端各 3 项全 PASS）
players=2 ids=[1 <client>] auth=[1 <client>] colors=[yellow blue]——生成所有玩家小鸡 / 颜色正确 / authority 正确
- **坑**：① RPC 广播进关卡（两端同时 change_scene，避免一端先进导致同步 Node not found）② client 的 `multiplayer.get_peers()` 返回 [1]（host），构造颜色表须 `colors[1]="yellow"` + 自己的 unique_id 也设色，不能依赖假 id=2 ③ rpc() 返回 void 不能赋值 ④ 验证脚本 stage 忘递增会卡死
- 回归 MainMenu / CharacterSelect / Level01 零错误

## 修复联机同步 4 个 bug（同电脑双实例 ENet 验证全 PASS）
用户反馈：① 主机看不到客机小鸡移动（画面卡死无动画）② 客机看主机移动但动画全是 stop 帧 ③ 主机看不到客机下的蛋但能挤到蛋、踩踏不碎 ④ 客机能看主机下的蛋，客机踩碎后主机画面不同步。

### 根因（Godot 4.6 引擎行为，均查源码确认）
1. **MultiplayerSynchronizer 不会自动跟随根节点 authority**：`chicken.set_multiplayer_authority(pid)`（递归默认 false）只设置小鸡本身，子节点 NetSync 的 authority 仍是 1 → 客机的小鸡同步器 authority≠自己 → 客机从不发送状态 → 主机看到的客机小鸡位置冻结（host→client 正常因为主机同步器 authority=1=自己）。→ 修复：`set_multiplayer_authority(pid, true)` 递归设置。
2. **非 authority 小鸡 `_physics_process` 直接 return** → `_update_animation()` 从不执行 → 远端小鸡永远停在 stop。→ 修复：非 authority 分支改为 `_update_animation()` 后 return（位置/velocity/current_state/朝向已由同步器提供）；chick.tscn 复制列表增加 `.:velocity`、`.:current_state`（需 @export）、`AnimatedSprite2D:scale`。
3. **`MultiplayerSpawner.spawn()` 非 authority 直接返回 null**（源码 `ERR_FAIL_COND_V(!is_multiplayer_authority(), nullptr)`，返回 Node 而非 Error）→ 客机下蛋 `spawned` 恒 null 走 fallback 本地 add_child，且客机非 spawner authority 时 spawn_path 自动同步也不触发 → 蛋只存在客机本机。→ 修复：客机下蛋改为 `_request_spawn_egg.rpc_id(1,...)` 请求主机代生成（主机调 spawner.spawn 广播所有端）。
4. **碎蛋 `stomp_break()` 只改本地 is_broken 无网络同步** → 任意端踩碎他端不同步。→ 修复：stomp_break 改 `@rpc("any_peer","call_local","reliable")` 幂等广播 + `broadcast_break()` 辅助（多人 .rpc()/单机直接调），3 处调用点（_check_stomp_hit/_on_body_entered/生命周期到期）统一走 broadcast_break。
- 附带：蛋释放改 **authority-only**（`_free_after_break` 非 authority 直接 return），避免双端同时 queue_free 触发 on_despawn_receive ERR_UNAUTHORIZED 竞态；`_spawn_egg_net` 加确定性命名 `EggNet_N`（各端生成顺序一致→节点路径一致→蛋上 RPC 可按路径路由）+ `ignore_chicken` 节点路径解析免碰撞。

### 验证（双实例 ENet headless，4 项全 PASS）
客机小鸡位置同步（host 看到 x 变化）/ 状态同步（PECKING=5 到达 host）/ 客机蛋到达 host（owner=客机 peer id）/ host 碎蛋广播到客机（broken=true）
- **坑**：① Godot 4.6 单机也有 **OfflineMultiplayerPeer**（has_multiplayer_peer() 恒 true，uid=1，is_server=true）——单机下蛋也走 spawner 路径是正常现象 ② **ENet 客机 peer id 是随机大数**（非 2/3/4），测试不能硬编码 id，用 is_server() 分支 + 实际 peer 列表 ③ 测试瞬移小鸡避开平台实心砖柱（Level01 平台 x∈[384,592] 是实心柱，蛋生成在砖块内会被物理弹飞穿地，是测试环境问题非游戏 bug）④ 客户端加载晚于主机时引擎打印 "Node not found: Level01/Chick/NetSync" 瞬时警告——良性（同步随后恢复），真实流程两端几乎同时加载
- 回归 Level01 / chick 场景 headless 零错误

## 真机联机仍冻结/蛋不出现 → 深挖出"同步路径缓存永久损坏"根因（v2 修复）
用户实测反馈：① 主机仍看不到客机小鸡移动（永远冻结）② 客机下蛋两端都不出现。headless 直接调方法的测试全过 → 改用**完全模拟真实流程**的测试（Lobby 建连 → _start_game_with_colors.rpc 广播进关卡 → Input.action_press 真实输入）复现问题。

### 真正的根因（Godot 4.6 MultiplayerSynchronizer 路径缓存）
**同步器在注册时会立即发送一次初始状态**（即使属性无变化）。若接收端关卡节点尚未创建（两端进关卡时序不一致，如客机先加载完），接收端对 `Level01/<chick>/NetSync` 的路径映射缓存失败后**永久不再重试**（等 8s 仍不同步）→ 该路径同步数据被永久丢弃 → 远端小鸡永远冻结。蛋不受影响（走 MultiplayerSpawner，不走同步器路径缓存）→ 解释了"蛋正常、位置冻结"的分离现象。

### 修复：关卡就绪握手 + 同步器占位 authority（三处）
1. **MultiplayerManager**：新增 `level_ready_received` 标记 + `@rpc("authority","call_local","reliable") notify_level_ready()`（主机广播关卡就绪；路由到 autoload 恒存在，避免 RPC 目标未生成）。
2. **LevelBase**：`_ready` 末尾握手——主机 `MultiplayerManager.notify_level_ready.rpc()`；客机若已收到广播则直接解锁；`_on_network_level_ready()`/`_notify_players_ready()` 遍历小鸡调 `set_play_ready(true)`。
3. **ChickenBase**：`play_ready` 标记（单机恒 true）；`_physics_process` 开头未就绪直接 return（不产生状态变化 → 不发数据）；**`set_play_ready` 时把 NetSync 的 authority 从占位 0 恢复为 player_id**（同步器 `_start()` 重新注册开始发送，此时接收端节点已存在）。
4. **LevelBase._spawn_players**：`set_multiplayer_authority(pid, false)`（不再递归）+ **NetSync 单独 `set_multiplayer_authority(0)` 占位**（authority=0 没有任何 peer 是它 → 同步器不发送；Godot 源码确认 0 不会被转成 1）。小鸡名字改**确定性命名 `Chick_%d` % pid**（替代 Godot 的 `@CharacterBody2D@7` 重命名，含 @ 的路径有隐患）。

### 验证（双实例 ENet headless 完全模拟真实流程）
- 无延迟（同时进关卡）：客机位置同步 ✓ 蛋 ✓ 碎蛋同步 ✓ PASS
- **极端时序（主机延迟 2s 进关卡，客机先加载立即下蛋）**：修复后 PASS 且**无任何 Node not found**（占位 authority 阻止早发初始状态）；修复前必现 "Node not found: Level01/Chick_x/NetSync" + 位置永久冻结
- 单机 Level01 / chick 场景 headless 零错误

### 测试脚本坑（复现测试经验）
① 测试驱动必须**在 change_scene 前挂到 root**（root 直接子节点不随 change_scene 释放），且 `_ready` 里 add_child 到 root 必须 `call_deferred`（场景树设置子节点期间 add_child 报 "Parent node is busy"）② 客机收到主机进关卡 RPC 会 change_scene 释放本场景 → await 协程被取消，驱动逻辑必须在常驻节点（root/autoload）上 ③ 每次测试前清理残留 Godot 进程（僵尸进程占 9999 端口导致 create_room 失败、客机连到僵尸主机）④ Input.action_press 模拟真实输入路径有效

## 联机架构解耦收尾：消除切 Steam 的硬编码（对照《联机解耦开发指导文档》）
用户问"联机解耦了吗？之后要转 Steam？"——逐项对照文档检查后发现 6 处硬编码会在 Steam 后端失效，全部修复并回归 PASS。

### 修复清单（后端无关化）
1. **`multiplayer.is_server()` → `MultiplayerManager.is_server()`**（LevelBase._ready 握手、ChickenBase._spawn_egg）：Godot 的 `is_server()` 实现是 `get_unique_id()==1`，Steam 下主机 id 非 1 会恒 false → 主机被误判为客机。
2. **`rpc_id(1, ...)` → `.rpc()` 广播 + 主机 guard**（ChickenBase 下蛋 → request_egg_spawn）：Steam 下主机 id 非 1，硬编码发 1 会丢。广播后 `request_egg_spawn` 内 `if not is_server(): return` 保证只有主机执行（2-4 人规模可接受）。
3. **`@rpc("authority")` → `@rpc("any_peer","call_local")`**（CharacterSelect._start_game_with_colors）：场景节点默认 authority=1，Steam 下主机非 1 会被 authority 型 RPC 拒绝。⚠️ 注意：进关卡 RPC 是**所有端都要执行**（各端自己加载关卡），不能加主机 guard（曾误加导致客机不进关卡，回归抓出）；"只有主机发起"由调用端 `_on_start_pressed` 的 is_server guard 保证。
4. **联机判定 `multiplayer.has_multiplayer_peer()` → `MultiplayerManager.is_network_connected()`**（LevelBase._spawn_players、LevelBase 握手、ChickenBase play_ready）：Godot 4.6 单机也有 OfflineMultiplayerPeer 恒 true，单机误判联机会导致 `get_my_id()`=0 → 小鸡 authority=0 不可控。
5. **Lobby**：`set_network_backend(ENetBackend.new())` → 加 `@export var use_steam: bool`，按 `SteamBackend.new() if use_steam else ENetBackend.new()` 切换（SteamBackend 是骨架占位、不引用 Steam 符号、编译通过）。
6. **遗留死代码**：`network/NetworkManager.gd` + `network/PlayerSync.gd` 无任何引用（grep 确认），建议删除（暂未删）。

### 验证
- 单机：play_ready=true、pid=1（不再 0）、下蛋/碎蛋 PASS
- 双实例 ENet 回归：客机位置同步 / 蛋 / 碎蛋双向同步全 PASS，无 Node not found
- 修正过程中误加 guard 导致客机不进关卡 → 回归抓出并修正（教训：进关卡类 RPC 各端都要执行）
