1. **GameManager.gd（断线中枢，autoload 全场景存活）**：
   - `_ready` 里 `call_deferred` 绑定信号（⚠️ autoload 顺序 GameManager 在 MultiplayerManager **之前**，直接 connect 会空指针）

   - `leave_network()`：主动离开抑制误报——`_leaving_room` 标志延迟 1s 清除（ENet close 后可能补发 server_disconnected，不抑制会在主菜单上闪"主机丢失"遮罩）
   - `return_to_main_menu()` 统一：is_online 时调 leave_network() 断开（覆盖暂停菜单/选角返回/断线强制三条路径）
2. **CharacterSelect.gd**：多人开始不再 `_start_game_with_colors`（原硬编码 start_level(1)），改广播 `_goto_level_select.rpc(color_dict)`（any_peer+call_local）→ 各端 `GameManager.start_level_select()`；返回按钮简化为直接 return_to_main_menu（统一断开）

## 联机解耦复查（对照文档逐条核查，补漏 3 处 + 清死代码）
用户再次确认"游戏逻辑层与联机层解耦了吗"。全面 grep 核查后修复：

1. **`multiplayer_manager.gd` notify_level_ready 仍是 `@rpc("authority")`**（上次只改了 CharacterSelect，这个漏网）：
   autoload 节点 authority 恒为 1，Steam 下主机 unique_id ≠ 1 → 广播被拒 → 就绪握手失效 → 同步器早发初始状态 → 远端小鸡永久冻结。改 `@rpc("any_peer","call_local","reliable")`。
   ⚠️ 教训：**凡"广播给所有端"的 RPC 一律 any_peer+call_local，包括挂在 autoload 上的**；authority 型仅适合单目标权威调用。
2. **`EggBase.broadcast_break()` / `ChickenBase._setup_camera()` 用 `multiplayer.has_multiplayer_peer()` 判联机**：
   Godot 4.6 单机 OfflineMultiplayerPeer 恒 true，虽功能等价但语义混乱、违背"游戏逻辑层不碰 multiplayer 原生"。统一改 `MultiplayerManager.is_network_connected()`。
3. **删除零引用死代码** `network/NetworkManager.gd(+uid)`、`network/PlayerSync.gd(+uid)`：
   NetworkManager 已被 ENetBackend 取代（enet_backend 头注释"移植自"），PlayerSync 已被 MultiplayerSynchronizer 取代；grep 确认仅注释/文档提及，无代码/tscn 引用。

### 核查结论（达标项）
- 后端实现类（enet/steam_backend）与 Lobby 注入点引用 ENet/Steam → 属网络实现层，正常
- 游戏逻辑层（player/levels/mechanisms/collectibles/ui 除 Lobby）不再有 ENet/Steam 引用、无 rpc_id、无 multiplayer.is_server()/get_unique_id 判断（仅 get_peers 通用 API 与 is_multiplayer_authority 物理权限判定）
- RPC 全部 any_peer（Lobby/CharacterSelect/LevelSelect/egg spawn/碎蛋/握手），无 @rpc("authority") 残留
- 网络对象生成走 MultiplayerSpawner（蛋）；位置/状态用 MultiplayerSynchronizer
