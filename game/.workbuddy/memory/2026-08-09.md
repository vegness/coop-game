## 蛋压碎逻辑修复（下蛋不再秒碎）
- 用户反馈：蛋一下下来就碎。根因：蛋生成在鸡身下，鸡反冲下落砸到蛋，body_entered 立即触发压碎。
- **修复**（EggBase.gd）：
  1. `age` 无条件累加 + `BREAK_GRACE_TIME=0.8s` 宽限期：蛋生成后 0.8s 内不压碎
  2. `egg_grounded` 落地稳定锁定：连续 >3 帧低速（<25）才锁定，锁定后保持（不依赖碰撞瞬间蛋速度）
  3. 压碎检测改用**蛋顶接触带面积查询**（34x8 矩形，中心在蛋顶，mask=Player），检测到 ChickenBase 且 `prev_velocity.y > 260` 才碎
  4. `ChickenBase` 新增 `prev_velocity` 成员（move_and_slide 前赋值）——因为 CharacterBody2D 碰撞后 velocity 被修正为 0，必须读碰撞前一帧速度
- **踩坑**：RigidBody2D 的 `body_entered` / `get_colliding_bodies()` / `intersect_shape(蛋体)` 对"相切接触"（鸡底=蛋顶，0 距离）都不可靠——鸡被蛋挡住停在表面从不进入蛋体。只有"蛋顶接触带"（覆盖蛋顶上下 4px 的细矩形）能稳定命中。
- **验证**：下蛋落地 exists=true/broken=false（不再秒碎）→ 鸡高速(vy=600)踩蛋 → 蛋消失（压碎销毁）✓；最终回归零错误。

## 踩踏后恒定上升 bug + 挤蛋功能（2 项修复）
用户反馈：①踩碎蛋后小鸡以恒定速度向上飞 ②鸡蛋碰撞粗糙，小鸡要能挤动鸡蛋。

### Bug 根因（恒定上升）
- `_physics_process` 顺序：`_check_stomp_hit()`（踩蛋 → state=FALLING, vy=-220）**之后紧跟落地检测** `check_on_floor()`
- 鸡刚撞到蛋，`is_on_floor()`（move_and_slide 碰撞检测）返回 true → `_on_landed()` **把 state 覆盖成 GROUND**
- GROUND 状态 `_apply_gravity` 直接 return（重力被跳过）→ 鸡带着 vy=-220 **恒定速度无限上升**，且 GROUND 没有"离开地面转 FALLING"的状态转换
- **修复**：落地判定加 `velocity.y >= 0.0` 条件（`if on_floor and not was_on_floor and velocity.y >= 0.0`）——踩蛋反弹瞬间 vy=-220<0 不触发落地，正常下落 vy≥0 正常落地
- 调试方法：_apply_gravity/_check_stomp_hit 加条件 print 观察 state（[S]/[G] 日志在踩蛋后消失 = state 变 GROUND 不满足打印条件）
- 实测修复：vy 序列 -220→-203.7→…每帧+16.3（重力恢复）→过 0 →正值→落地 0，标准抛物线

### 挤蛋功能
- ChickenBase 加 `@export egg_push_force=900.0` + `_push_eggs()`：move_and_slide 后遍历 slide collisions，撞到 EggBase 且**法线水平**（abs(normal.x)>0.5）→ `egg.apply_force(-normal * egg_push_force)`；站蛋上/踩蛋（法线垂直）不推
- 实测：鸡按住右键推蛋 2s，蛋被推走 187px（修复前仅靠 CharacterBody2D 物理推动 27px，不稳定）

## 走出平台浮空修复 + 掉坑传送回最后落脚点（2 项修复）
用户反馈：①小鸡走出平台边缘会浮空 ②掉进沟应传回上一次落脚点、蛋不能在坑中留存。

### 浮空修复（ChickenBase）
- 根因：`_update_state_transitions()` match 只有 JUMPING/FALLING/EGG_LAID/GLIDING 分支，**GROUND 无分支**——走出平台边缘后 is_on_floor()=false 但 state 仍 GROUND → `_apply_gravity` 对 GROUND 直接 return（重力被跳过）→ 浮空
- 修复：GROUND 分支加 `if not is_on_floor(): state=FALLING + _on_fall_start()`（is_on_floor 是上一帧 move_and_slide 结果，晚一帧无妨）
- 注意：这与此前"踩蛋恒定上升"是同一类问题（GROUND 状态重力被跳过 + 无转出分支），两处都补了

### 掉坑传送（Level_01 + ChickenBase）
- **ChickenBase** 加 `last_landed_position`：`_on_landed()` 里记录 `global_position`（每次落地更新）
- **Level_01._on_level_process**：y>FALL_Y_THRESHOLD 时 `ch.revive(ch.last_landed_position)`（若 ZERO 回 spawn_position）——不再固定回出生点
- **沟变无底深渊**：`_paint_terrain()` 删除沟底砖墙循环（原 y=45..55 tile 物理 y=720..896）→ 鸡掉沟持续下落 y>900 触发传送；蛋掉沟 y>900 由 EggBase._physics_process 销毁（蛋不入坑留存）
- 验证：6 项 PASS——站平台2(last_landed 记录) / 走出平台下落(dy=127.9) / 掉沟传回 last_landed / 蛋掉沟销毁
- 坑：验证脚本 match 分支内 `var` 是块级作用域（跨 stage 访问要成员变量）；`and freed_引用` 判断不可靠（用 is_instance_valid）

## 三项修复：跳跃蓄力帧 / 多人界面残留 / 下蛋反弹后再跳一次
用户反馈：①jump 动画 1.png 是地面蓄力帧不应参与空中循环 ②多人→主菜单→单人时选角页还是多人界面 ③下蛋反弹后应允许再跳一次（但不能下蛋）。

### ① 跳跃动画（ChickenBase + ChickPlayer）
- ChickPlayer：jump 动画拆成 `jump_start`（[1] 帧，取自 jump/1.png，loop=false）与 `jump`（[2,3,4] 循环）；`_add_anim_frames` 加 dir_name 参数（动画名≠目录名时用）
- ChickenBase：`_jump_start_timer`（JUMP_START_SHOW_TIME=0.12s），`_perform_jump`（地面起跳）置 timer，`_physics_process` 递减，`_update_animation` 在 timer>0 时锁定播 jump_start；空中跳（_perform_air_jump）不播蓄力帧
- 坑：jump_start 帧在 jump/ 目录（动画名与目录名不同，加载需指定目录）

### ② 多人界面残留（GameManager + MainMenu）
- 根因：多人回主菜单后 `GameManager.is_online` 未重置为 false → 再点单人影进选角页 is_multiplayer=true
- 修复：`GameManager.return_to_main_menu()` 里加 `is_online = false`；MainMenu._on_single_player 也显式 `is_online = false`（双保险）

### ③ 下蛋反弹后再跳一次（ChickenBase）——【已还原，用户澄清需求】
- **第一次理解错误**：实现了"下蛋（二段跳）反弹后可再跳一次"（can_air_jump_after_egg）——用户澄清：**刷新跳跃应该来自"踩踏碎蛋"，不是下蛋**
- **还原**：删除 can_air_jump_after_egg 相关（_handle_jump_input 分支、_perform_egg_lay 置位、_on_landed 重置）
- **正确实现**：`can_air_jump_after_stomp`：`_check_stomp_hit` 踩碎蛋时置 true（踩踏刷新跳跃）；`_handle_jump_input` 空中跳分支**优先级高于下蛋**（否则踩踏时若没下过蛋按跳会走下蛋分支）；`_perform_air_jump` 置 false + `has_laid_egg_this_cycle = true`（该次跳跃不能下蛋）；`_on_landed` 重置
- 验证：5 项 PASS——下蛋路径不刷新（还原 ✓）/ 踩踏碎蛋后刷新标记 true / 踩踏反弹按跳 vy=-82 向上且蛋数不变 / 已下蛋标记 true
- 坑：踩踏碎蛋反弹后状态是 FALLING（不是 EGG_LAID），空中跳分支条件用 JUMPING/FALLING 即可；验证脚本里碎蛋 0.6s 销毁导致蛋数对比错乱（egg_count_before 记踩踏前）

### 踩坑（重要）
1. **tscn 节点块内不要写 `#` 注释**——Godot 4.6 解析器会把注释后同一层级的 `[node ...]` 块吞掉（CollisionShape2D 静默丢失，仅实例化后 get_node 才暴露）。注释要放在 `[gd_scene]` 头或文件顶部
2. **槽位 setup() 必须在 add_child 之后调用**（否则 @onready 未初始化 → nil 访问报错）
3. **双实例验证时序**：两进程 t0 不同步（client 延迟启动），host 检查必须用"条件轮询+超时"而非固定毫秒；host 的 change_scene 不能放 autoload _ready（会 "Parent node is busy"），延迟到 _process 首帧
4. **autoload 脚本 _ready 里 change_scene 太早**会报 Parent busy——延迟一帧/定时器
