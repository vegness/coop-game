# Godot + VSCode + CodeBuddy 开发注意事项

## 一、环境配置

1. **Godot 版本**：固定使用 Godot 4.x（推荐 4.2+），禁止混用 3.x 语法
2. **CodeBuddy 设置**：配置快捷键快速唤起，绑定顺手的热键（如 `Ctrl+Shift+C`）
3. **VSCode 插件**：保留 Godot Tools 插件确保 GDScript 语法高亮和 LSP 支持
4. **LSP 端口**：确认 `settings.json` 中端口与 Godot 编辑器设置一致（默认 6005）
5. **Godot 路径**：`settings.json` 中的编辑器路径填写绝对路径，避免相对路径失效
6. **文件排除**：VSCode 排除 `.godot/` 缓存和 `*.tmp` 临时文件
7. **热重载**：配置 `launch.json` 支持从 VSCode 直接启动 Godot 调试

## 二、项目结构

8. **目录规范**：使用标准结构（`autoload/`、`player/`、`levels/`、`ui/`、`assets/`、`network/`）
9. **场景预制体**：所有可复用实体（玩家、敌人、道具、陷阱）做成 `PackedScene`
10. **单例管理**：AutoLoad 管理 GameManager、NetworkManager、AudioManager 等全局状态
11. **资源路径**：统一使用 `res://` 相对路径，禁止绝对路径
12. **命名规范**：`.tscn` 与 `.gd` 文件保持同名，节点名使用 PascalCase
13. **脚本分离**：联机逻辑单独抽离（如 `PlayerSync.gd`），不与本地逻辑混写

## 三、与 CodeBuddy 协作

14. **版本声明**：每次对话开头明确声明"使用 Godot 4.x GDScript"
15. **上下文提供**：主动提供当前文件路径和相关文件列表，CodeBuddy 不会自动读取项目结构
16. **完整代码**：修改现有代码时，全选粘贴完整文件内容，不要只给片段
17. **分步实现**：复杂功能拆分为小任务，逐步生成，不要一次性要求过多
18. **报错反馈**：提供完整报错信息（含行号、文件路径），不要只描述现象
19. **具体需求**：避免模糊描述（如"手感不好"），提供具体参数和预期行为
20. **方案先行**：复杂功能先让 CodeBuddy 出方案/伪代码，确认后再生成完整代码
21. **代码审查**：AI 生成代码务必人工检查，特别是 `@rpc` 和同步逻辑
22. **保存模板**：将常用提示词保存到 VSCode Snippets 或备忘录，避免重复输入

## 四、联机/网络开发

23. **网络方案**：优先使用 Godot 内置 `ENetMultiplayerPeer`
24. **主机区分**：所有网络代码必须区分 `multiplayer.is_server()` 和客户端逻辑
25. **RPC 注解**：远程调用必须使用 `@rpc` 注解，明确指定调用模式
26. **同步器使用**：使用 `MultiplayerSynchronizer` 同步位置/状态，不要每帧手动 RPC
27. **同步频率**：合理设置同步间隔，避免过于频繁导致卡顿
28. **本地预测**：玩家输入本地立即响应，再通过同步校正，降低延迟感
29. **防火墙端口**：联机测试注意防火墙放行，开发阶段先用 `127.0.0.1` 本地测试
30. **断线处理**：设计断线检测和重连机制，避免崩溃
31. **多实例测试**：同时运行多个 Godot 实例测试联机功能

## 五、代码质量

32. **类型注解**：尽量使用静态类型（`: int`、`: Vector2` 等），提升可读性和性能
33. **信号机制**：使用 `signal` 解耦通信，避免直接引用耦合
34. **物理/渲染分离**：移动逻辑放 `_physics_process()`，UI 更新放 `_process()`
35. **输入映射**：在 Godot 项目设置中配置 `Input Map`，代码中使用 `Input.is_action_pressed()`
36. **资源加载**：关卡切换使用 `ResourceLoader.load_threaded_request()` 避免卡顿
37. **内存管理**：及时调用 `queue_free()` 释放节点，避免内存泄漏
38. **注释规范**：复杂联机逻辑添加注释说明同步时机和 RPC 调用方向

## 六、美术与资源

39. **像素比例**：Viewport 使用 `Canvas Items` 缩放模式，保持像素清晰
40. **图集优化**：像素素材使用 SpriteFrames 管理动画，减少 Draw Call
41. **碰撞体**：`CollisionShape2D` 尽量贴合像素轮廓
42. **Z-Index 层级**：明确场景、玩家、UI 的 `z_index`，防止渲染顺序错误

## 七、调试与测试

43. **频繁提交**：每完成一个功能点立即 `git commit`
44. **日志输出**：使用 `print()` 或 `push_warning()` 输出关键状态
45. **性能监控**：使用 Godot Debugger Monitors 关注 FPS、节点数、网络流量
46. **边界测试**：测试极端情况（如 4 人同时跳跃、断网、快速重连）

## 八、安全与合规

47. **敏感信息**：不硬编码 IP、端口，使用外部配置文件
48. **版本统一**：团队协作统一 Godot 版本，避免 `.tscn` 格式冲突
49. **备份策略**：定期备份项目，AI 生成代码可能引入隐性 bug
50. **代码所有权**：AI 生成的代码需理解后再使用，不要无脑复制
