## 一、目标与范围

### 1.1 本次目标（文档阶段）

1. 主菜单游戏模式入口收敛为两个：**单人硬行**、**多人模式**（原**设置**/退出按钮保留）
2. 多人模式点击后 → **多人联机大厅**（IP 连接：创建房间 / 输入 IP 加入）→ 连接成功 → **多人模式选择**（多人闯关 / 多人对战）
3. 多人对战进入后先到 **对战玩法选择（BattleModeSelect）**：6 种已规划玩法 + 开发中占位 + **混合模式**
4. 多人闯关复用既有合作链路；多人对战为**新增玩法**，本文档给出各玩法设计草案与实现路径
5. **其余接口暂时不变**：`GameManager` / `MultiplayerManager` / `LevelBase` / 既有 Lobby 网络逻辑均不修改

### 1.2 明确不做（本次）

- ❌ 不修改任何 `.gd` / `.tscn`（包括 MainMenu、Lobby）
- ❌ 不改动 `GameManager` / `MultiplayerManager` 现有方法与信号

### 2.5 ModeSelect（多人模式选择，新增场景）

- 结构：与 MainMenu 同风格（糖果色面板 + 两按钮）
- 按钮：
  - **多人闯关** → `GameManager.start_character_select()`（沿用既有多人选角 → 关卡链路；`GameManager.current_mode = MULTI_COOP`）
  - **多人对战** → 切到 `BattleModeSelect.tscn`（对战玩法选择）
- 返回：回 `Lobby`（仅断开语义由 GameManager 统一处理）；返回主菜单仍走 `GameManager.return_to_main_menu()`
- 断线兜底：`GameManager._on_server_lost`（autoload 全场景存活）已覆盖 —— 主机掉线自动弹遮罩回主菜单，无需本场景额外处理

### 2.6 BattleModeSelect（对战玩法选择，新增场景）

- 结构：糖果色面板 + 玩法列表（网格或纵向列表）
- 按钮清单：
  | 玩法 | 文案 | 行为 |
  | ---- | ---- | ---- |
  | 蛋球赛 | 下蛋踢进对方球门 | 单选 → 进入该玩法 |
  | 挤出局 | 把对手挤下屏幕 | 单选 → 进入该玩法 |
  | 竞速赛 | 先到终点者胜 | 单选 → 进入该玩法 |
  | 孵化赛 | 比谁孵化的蛋多 | 单选 → 进入该玩法 |
  | 啄米地鼠 | 啄人 vs 探头吃米 | 单选 → 进入该玩法 |
  | 真假小鸡 | 捉捕者 vs 模仿者 | 单选 → 进入该玩法 |
  | 更多玩法 | 开发中… | 置灰占位（disabled） |
  | 混合模式 | 选 ≥2 种玩法轮换 | 弹多选面板 → BattleDirector |

- 返回：回 `ModeSelect`
- 玩法枚举建议独立（见 5.2），不塞进 `GameMode`

## 三、多人对战玩法草案（规划）

### 3.1 定位

复用既有"下蛋反冲 + 蛋交互 + 机关"物理系统，做**轻量竞技**。所有玩法共用 Chicken / Egg / Mechanism 体系，不引入新物理体系、不新增鸡类型（个别玩法可用现有鸡种组合）。

### 3.2 玩法总览

| # | 玩法 | 一句话规则 | 胜利条件 | 复杂度 |
| - | ---- | ---------- | -------- | ------ |
| 1 | 蛋球赛 EggBall | 下蛋并把蛋踢进对方球门 | 先得 N 球 / 限时得分多者胜 | 中 |
| 2 | 挤出局 KnockOut | 把对手挤出屏幕视野 | 最后留在场上的玩家胜 | 低 |
| 3 | 竞速赛 Race | 全员同场计时跑图 | 先到终点排名，名次给分 | 低 |
| 4 | 孵化赛 HatchRace | 蛋延迟孵化，可踩碎对方蛋 | 限时内孵化数最多者胜 | 中 |
| 5 | 啄米地鼠 PeckMole | 一人啄，其余探头吃米 | 吃米得分；被抓淘汰，存活者结算 | 中 |
| 6 | 真假小鸡 ImposterChicken | 捉捕者 vs 模仿者，模仿人机行为 | 捉捕者找出所有模仿者 / 模仿者撑到时间结束 | 高 |
| 7 | （更多玩法） | 开发中占位 | — | — |
| 8 | 混合模式 Mixed | 选 ≥2 种玩法轮换 | 各轮积分累加，总积分最高者胜 | 中 |

### 3.3 各玩法详细设计

#### 3.3.1 蛋球赛（EggBall）

- 地图：对称球场（左右各一门），复用现有平台机关做障碍
- 规则：下蛋生成"球蛋"（特殊蛋，不受碎蛋/孵化逻辑影响），用身体/反冲/啄击把蛋撞进对方球门；蛋出界由主机复位到中场
- 胜利：先得 3 球，或限时（如 3 分钟）得分多者胜
- 实现要点：球蛋复用 RigidBody2D 蛋物理 + 门区 Area2D 判定；进球广播 `@rpc("any_peer","call_local")`
- 复杂度：中（球蛋状态机 + 进球判定 + 复位）

#### 3.3.2 挤出局（KnockOut）

- 地图：悬浮平台竞技场（四周无墙，掉出屏幕即淘汰）
- 规则：把对手挤下平台（身体碰撞 / 蛋反冲 / 蛋击退）；被挤下后**不复活**，直到只剩 1 人
- 胜利：最后留在场上的玩家胜
- 实现要点：复用"掉坑/出界"检测；淘汰即 `set_play_ready(false)` 冻结或移出舞台；观战模式后续再说
- 复杂度：低（几乎纯地图 + 淘汰判定）

#### 3.3.3 竞速赛（Race）

- 地图：优先复用闯关关卡子集（如 level_01/02），同场起跑
- 规则：全员同时从起点出发，先到达终点区域者排名靠前；允许互相踩蛋、推挤
- 胜利：按到达顺序给分（第 1 名 5 分、第 2 名 3 分……），混合模式中累加
- 实现要点：复用 ExitArea 目标检测 + 到达顺序记录（主机权威）
- 复杂度：低

#### 3.3.4 孵化赛（HatchRace）

- 规则：下蛋后蛋**不碎**而是进入孵化计时（如 5s），到期孵化出小鸡蛋（计 1 分，可保留/消失）；**踩在对方蛋上可将其踩碎**（对方不得分）
- 胜利：限时（如 60s）内孵化数最多者胜
- 实现要点：改造 EggBase 生命周期（碎 → 孵化两态）；"踩碎"用体重判定（蛋承受压力超过阈值）
- 复杂度：中（蛋生命周期改造是核心，注意与既有 EggBase 兼容——建议新增 `HatchEgg` 子类而非改基类）

#### 3.3.5 啄米地鼠（PeckMole）

- 规则：每轮一人为"啄手"，其余玩家在掩体内**探头吃米**（按键探出，米随机出现在掩体上方）；啄手靠近并啄击，被抓者淘汰
- 胜利：啄手淘汰全部对手则赢；反之限时结束，存活吃米多的玩家赢（角色轮换）
- 实现要点：掩体=可进出平台；探头状态同步（动画 + 可啄判定）；啄手由主机轮换
- 复杂度：中（角色轮换 + 探头状态机）

#### 3.3.6 真假小鸡（ImposterChicken）

- 规则：场地有 N 只**人机小鸡**按固定节奏做动作（跑/跳/啄等）；1 名捉捕者，其余为模仿者混在人机里，需模仿人机动作；捉捕者按 E 啄击任意小鸡，啄到真玩家则该玩家淘汰，啄到人机无惩罚但可暴露位置
- 胜利：捉捕者找出全部模仿者 / 模仿者存活到倒计时结束（如 90s）
- 实现要点：**人机小鸡**（脚本 AI 循环播动作动画，与玩家共用 ChickenBase 外观）；动作状态同步（复用现有 current_state 同步）；"啄击目标"判定复用啄击逻辑
- 复杂度：高（人机 AI + 混淆判定），列为最高优先级之外的后续项

### 3.4 混合模式（Mixed，BattleDirector）

- 入口：BattleModeSelect 勾选 **≥2 种**玩法（最多 3 种，避免一局过长）
- 轮次：每轮随机或顺序抽取一个玩法（主机权威决定并广播），单局时长按玩法预设（如 60~120s）
- 积分：每个玩法结算后按名次给分（BattleBase 提供统一 `get_round_scores()` 接口），BattleDirector 累加
- 结束：全部轮次打完 → 总积分榜 → 返回 BattleModeSelect 或再来一局
- 架构：`BattleDirector`（轮次管理，extends Node，挂在对战根节点）加载/卸载各玩法场景；玩法场景只做单局逻辑，不感知轮次
- 复杂度：中（架构上先定 BattleBase 接口，混合模式是纯编排）

### 3.5 通用交互规则（所有玩法适用）

- **蛋击退**：蛋命中对手仅击退、无伤害（复用炸弹蛋击退逻辑，去掉伤害）
- **干扰**：部分玩法可让特定蛋（粘/冰/弹）对对手产生减速/滑倒/弹飞
- **复活**：除"挤出局"外，掉坑/出界 → 短延迟后出生点复活（复用既有复活机制）
- **倒计时**：一律主机权威计时（RPC 广播），不做本地计时

### 3.6 与闯关的差异（实现侧）

| 维度 | 多人闯关（既有） | 多人对战（规划） |
| ---- | ---------------- | ---------------- |
| 目标检测 | LevelBase 出口/收集 | BattleBase 结算逻辑（排名/计分） |
| 胜负广播 | 无（全员通关） | 主机广播结算 → 各端显示排名 |
| 地图 | 合作关卡（对称/非对称皆可） | 优先复用闯关地图，后做对称竞技图 |
| 玩家生成 | SpawnPoint1-4 同侧 | 按玩法：同场起跑 / 对称阵营 / 自由 |
| 生命周期 | 全员存活直到通关 | 可淘汰（挤出局）、可计分（孵化/蛋球） |

### 3.7 同步要点（沿用既有约定，勿另起炉灶）

- 玩家移动/状态：`MultiplayerSynchronizer` + 关卡就绪握手（`notify_level_ready`）
- 蛋生成：仅主机 spawner authority 生成，客机走 `request_egg_spawn` 广播
- 计时/分数/玩法选择：主机权威变量 → 同步器或 `@rpc("any_peer","call_local")` 广播
- 结算/轮次切换：`@rpc("any_peer","call_local")` 全端执行，**不加 guard**（发起端 is_server guard）

## 四、解耦约束（红线，实现时必须遵守）

1. **UI 层（MainMenu / Lobby / ModeSelect / BattleModeSelect / CharacterSelect）禁止直接 `multiplayer.*` 原生调用**
   - 连接状态/peer 列表 → `MultiplayerManager.is_network_connected()` / `get_peers()` / `get_my_id()`
   - 主机判断 → `MultiplayerManager.is_server()` / `is_host_peer(pid)`，**禁止 `pid == 1` 判断房主**
2. **禁止在 UI 里 `isinstance(MultiplayerManager.backend, SteamBackend)` 之类后端类型判断**；如确需区分（如 Steam 好友邀请按钮），由 MultiplayerManager 暴露后端无关的查询方法（预留）
3. **RPC 模式**：全端执行 → `@rpc("any_peer","call_local")` 不加 guard；仅主机执行 → `@rpc("any_peer","call_remote")` + 方法内 `is_server()` guard；**不用 `@rpc("authority")`**（Steam 下会被拒）
4. **场景流转全部经 `GameManager`**（`start_multiplayer` / `start_character_select` / `return_to_main_menu` 等），UI 不直接 `change_scene` 绕过状态机
5. 断线处理统一走 `GameManager`（autoload）：客机断线遮罩 / 主机踢人 toast 已全局覆盖，新模式选择页无需重复实现
6. **玩法与闯关解耦**：对战玩法做成独立的 `battle/` 目录与 BattleBase 基类，**不侵入 LevelBase / 既有关卡**；需要复用的（ExitArea、复活、蛋物理）通过继承/组合引用，不复制实现

## 五、接口变更清单（本次不动，仅预留）

### 5.1 明确不动（本次）

- `GameManager.GameState` / `GameMode`（暂不加枚举）
- `GameManager.start_multiplayer()` / `start_character_select()` / `return_to_main_menu()`
